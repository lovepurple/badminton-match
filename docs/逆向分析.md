## 2. 容器格式与解密

微信 PC 端 4.x 的 `.wxapkg` 是 `V1MMWX` 容器：

```
"V1MMWX"                                            6 字节
AES-256-CBC(file[6:1030], key, iv)[:1023]            明文头部
XOR(file[1030:], ord(appid[-2]))                    明文其余部分

key = PBKDF2-HMAC-SHA1(appid, b"saltiest", 1000, 32)
iv  = b"the iv: 16 bytes"
```

明文即标准 wxapkg：

```
0xBE | uint32 info1 | uint32 index_len | uint32 body_len | 0xED | uint32 count
count × ( uint32 name_len | name | uint32 offset | uint32 size )
body
```

两个容易踩错的点（实测得出）：

1. 头部只取 AES 解密的**前 1023 字节**，XOR 区从文件偏移 `1030` 开始。
2. `body` 起点是 `14 + index_len`（`index_len` 把 `count` 字段算在内），
   条目里的 `offset` 是**相对整个明文的绝对偏移**，不是相对 body。

工具：`tools/wxapkg.py`。

```bash
python tools/wxapkg.py wx5f3f808a2ea7f0a8 __APP__.wxapkg out/
```

## 6. 数据模型（原包字段）

```
race.multiRace[0]
  _infos.mode / type / wheelMode / partnerMode / groups / groupsValid / teamNames
  _rounds          局数 1|3|5
  _balls           每局分数
  _order           场次序号（追分模式用于计算满分）
  _rankMode        pointFirst | ballFirst | totalFirst | winsFirst
  _status          entering | playing | modify | end | cancel
  _scores[]        [{ score: [a,b] }]       每局比分
  _scoreAll        [win, lose]              局分
  _scoreChase      [a,b]                    追分模式累计
  _multiMode       赛制 mode
  allScores[]      同轮其他场次（追分续算）
```

本项目在 `shared/*.js` 中保留同名语义的字段（`scores` / `scoreAll` / `crt` / `status`），
不沿用 `_` 前缀。
