# 玩法开发指南（给 LLM / 开发者）

本仓库的「玩法」= 一个可插拔的代码模块。管理员在「玩法」后台调整展示与默认值；
**新增玩法由 LLM 按本指南在仓库里落地**，不需要改引擎。

读完这份文档你应该能：把一句“我想加个 XX 玩法”，变成一个可用的玩法模块 + 测试。

---

## 0. 先问清这 5 件事（缺一不可）

在写任何代码前，必须和需求方确认下面 5 项，并复述一遍确认无误。

| # | 问题 | 为什么要问 | 例 |
| --- | --- | --- | --- |
| 1 | **参与人数** | 决定 `min`/`max`、单打还是双打、是否需要轮空 | 8~16 人，双打 |
| 2 | **怎么玩** | 一句话讲清核心机制，写进 `rules.how` | 每人和其余人各搭档一次 |
| 3 | **怎么分组 / 怎么排对阵** | 决定用哪个排程原语（见 §3） | 轮转法，每轮 2 场 |
| 4 | **怎么结束** | 打满轮次？打满 N 场？先到多少分？ | 打满 7 轮，或每对打满 3 场 |
| 5 | **怎么计分** | 局数、每局分、胜负判定、是否追分、是否让分 | 三局两胜、每局 21 分、领先 2 分、30 分封顶 |

追问规则：

- 对方说“随便”“你定”，就用默认值：`三局两胜 / 每局 21 分 / 领先 2 分 / 30 分封顶`，并在回复里写明你用的默认值。
- 涉及“分数怎么算”时，一定要问：**每局独立计分，还是全场累计追分？**（后者对应 `scoring.mode = "chase"`）。
- 涉及“谁和谁打”时，一定要问：**搭档是固定、随机、还是强弱搭配？**（对应 `partnerMode`）。
- 人数与赛制冲突时（如 5 人打双打轮转），明确说明会轮空，并给出实际场次数。

把这 5 项写成 `docs/llm/plays/<id>.md`（模板见 §6），再动代码。

## 2. 模块契约

```js
module.exports = {
  id: "chase",                 // 唯一，等于 race.mode
  name: "追分赛",               // 展示名
  group: "singles",            // doubles | singles | match | teams（决定按人还是按队排名）
  min: 2, max: 8,              // 参与人数
  intro: "2 - 8人，单打连续追分",
  tags: ["单打", "追分"],

  scoring: { mode: "chase" },  // 可选：默认 "sets"；chase = 全场累计追分

  rules: {                     // 五段中文，必须写全，后台与创建页会展示
    people: "2 - 8 人，单打",
    how: "两人对打，每球得分，整场累计追分",
    groups: "轮转法排单打对位，每人打「每人比赛次数」场",
    end: "一方累计到设定分数且领先 2 分（30 分封顶）",
    score: "默认每场 30 分、一局定胜负"
  },

  defaults: {                  // 创建比赛时的初始值（管理员可在后台覆盖）
    rounds: 1, balls: 30, rankMode: "totalFirst", matchesPerEntity: 3
  },

  schedule(race, fmt) {         // 核心：返回对阵数组
    const entities = (race.players || []).map((p) => [p.id]);
    return fmt.fixedCountMatches(entities, race.matchesPerEntity || 3);
  }
};
```

`schedule` 返回值：

```js
[{ round: 1, court: 1, side1: ["p1", "p2"], side2: ["p3", "p4"] }]
```

- `round` 从 1 开始，用于分组展示与追分续航；
- `court` 决定同一轮的场地编号；
- 单人项目 `side1` 只有一个元素；
- 团体/对抗用 `group: "match"|"teams"`，并且需要 `teamA/teamB` 时见 `fmt.teamsMatches`。

## 3. 可直接复用的排程原语（`fmt.*`）

| 原语 | 用途 |
| --- | --- |
| `circleRounds(n)` | 轮转法，返回 n-1 轮的对位（保证两两相遇） |
| `makePairs(players, partnerMode)` | 双打搭档：`fixed` / `random` / `bylevel` |
| `roundRobinMatches(entities, doubleLoop)` | 循环赛（entities 是 `[ids]` 或搭档对） |
| `fixedCountMatches(entities, cap)` | 循环 + 每人/每对出场次数上限 |
| `eightMatches(players)` | 八人转（搭档互不重复） |
| `greedyCourts(pairs, playerCount)` | 只给“搭档组合”，按同一轮不重复原则凑成 4 人一场（混双转/前后转用） |
| `arenaMatches(entities, kings)` | 擂台：前 k 名为擂主 |
| `crossMatches(a, b)` | 两组之间两两对阵（对抗赛用） |
| `rotationCross(teamA, teamB, singles)` | 两队各自轮转后按序对打（轮比转用） |
| `teamsMatches(race, mode)` | 团体赛：队队循环拆成多个单项 |
| `promoteGroups(players, size)` | 晋级赛分组 |

写新玩法时**优先组合这些原语**；只有确实表达不了时才自己写排程，并在模块顶部注明原因。

## 4. 计分与结束（通用引擎，不要重写）

- 局数、每局分数、2 分差、30 分封顶、让分：`shared/rules.js`。
- 追分模式：`scoring.mode = "chase"`，引擎按“全场累计、本场满分 = 每局分数 × 局数”判定。
- 排名：`shared/ranking.js`（积分/净胜分/总得分/胜场 4 种）。

玩法只负责“谁和谁打”（`schedule`）和“用什么计分模型”（`scoring`）。
如果需求确实超出通用引擎（例如“每 5 分换人”“限时赛”），先停下来评估：多数情况可以通过
`defaults` + `schedule` 表达；真要改引擎，必须同时更新 `docs/规则还原.md` 与测试。

## 5. 实测清单（提交前必须全绿）

```bash
node tests/logic.test.js      # 规则 + 排程 + 排名
node tests/e2e.test.js        # 客户端数据层 ↔ 服务端
cd server && python -m pytest -q
```

手工验证（浏览器）：

1. 后台「玩法管理」能看到新玩法，规则五段正确；
2. 创建比赛时能选到它，默认局数/分制/排名方式符合预期；
3. 生成的对阵数量与你算的一致（写进测试断言）；
4. 记一场分，确认追分/局分表现符合描述。

## 7. 已实现玩法

| id | 名称 | 分组 | 说明 |
| --- | --- | --- | --- |
| `eight` | 八人转 / 超八转 | doubles | 轮换搭档，搭档互不重复 |
| `mixRound` | 混双转 | doubles | 每男与每女各搭档一次 |
| `weakStrong` | 前后转 | doubles | 前后半区各搭档一次 |
| `fixedRound` | 固搭转 | doubles | 固定搭档，各打 N 场 |
| `singlesRound` | 单打转 | singles | 每人打 N 场 |
| `loop` | 单循环积分赛 | doubles | 两两交手一次 |
| `doubleLoop` | 双循环积分赛 | doubles | 两两交手两次 |
| `arena` | 擂台赛 | doubles | 擂主迎接所有攻擂 |
| `chase` | 追分赛 | singles | 全场累计追分（`scoring.mode = "chase"`） |

其余（团队/接力/晋级等）仍是内置赛制，由 `shared/formats.js` 兜底，按需逐步迁移。

## 8. 完整示例：把「追分玩法」变成代码

需求原话：「加个追分的玩法，2~8 人单打，每球都算分，一路加到 30 分，谁先到谁赢。」

五要素 → 模块映射：

| 问题 | 答案 | 落到哪 |
| --- | --- | --- |
| 参与人数 | 2~8 人单打 | `group: "singles"`, `min: 2`, `max: 8` |
| 怎么玩 | 每球得分，全场累计 | `scoring.mode = "chase"` + `rules.how` |
| 怎么分组 | 轮转对位，每人 3 场 | `schedule` 用 `fixedCountMatches` |
| 怎么结束 | 先到 30 分（领先 2 分） | `defaults.balls = 30` + 引擎判定 |
| 怎么计分 | 整场累计、一局定胜负 | `defaults.rounds = 1`、`scoring.mode = "chase"` |

```js
schedule(race, fmt) {
  const entities = (race.players || []).map((p) => [p.id]);
  return fmt.fixedCountMatches(entities, race.matchesPerEntity || 3);
}
```

对应文件：`shared/plays/chase.js`（可直接当模板抄）。

---

## 9. 不要这样做

- ❌ 在玩法里重写“平局/2 分差/30 分封顶”判定 —— 那是 `rules.js` 的事。
- ❌ 在玩法里算排名 —— 排名只由 `ranking.js` 和 `entityKind` 决定。
- ❌ 直接改 `shared/formats.js` 的 `generate` switch 来加新玩法 —— 新玩法一律走 `shared/plays/`。
- ❌ 让 `schedule` 返回空数组或重复的对阵（引擎不会报错，但比赛会变成 0 场）。
- ❌ 忘记在 `registry.json` 注册 —— 模块存在但永远不会被加载。
- ❌ 只写代码不写 `rules` 五段 —— 后台和创建页会显示空规则，用户看不懂怎么玩。
