## 2. 单局判定（顺序不可调换）

源码：`record.js` 的 `_judgeZero → _judgeEqual → _judgeBalls → _judgeDiffer → _judgeRound`。

1. **0:0 不允许** —— “羽毛球不支持0:0的比分哦”
2. **平局不允许** —— “羽毛球没有平局，请至少再打一球”
3. **双方都未到本局分数** —— “本局未满 N 分，是否继续记分？”（可继续，也可直接结束本局）
4. **双方都 < 30 且分差 < 2** —— “分差未达2分，是否继续记分？”（可继续，也可直接结束本局）
5. 否则本局结束，分高者胜。

第 3、4 步是**软提示**：用户可以选择「下一局」直接采纳当前比分。

> 30 分封顶是源码硬编码（`t[0] < 30 && t[1] < 30`），不随分制变化。
> 因此 21 分制下 29:29 会提示，30:29 直接结束（即 30 分封顶）；
> 但 35/41/42 分制同样在 30 分处失去“必须领先 2 分”的约束，这是原实现的行为，本项目如实复刻。

## 3. 局数与整场判定

```
played >= rounds                                  → 已到约定局数
或 played > 1 且 任一方局分 >= rounds / 2          → 已到约定局数（三局两胜先到 2 局）
```

弹窗文案：`已到约定局数，是否完成记分？`（超过局数为“已超约定局数…”）。
取消 = 再打一局，确认 = 完成记分。

## 4. 追分模式（chase）

用于轮比转、接力赛、团体赛：

- 比分是**全场累计**，不是单局比分；每场对阵仍只记一局。
- 本场满分 = `每局分数 × 局数`；团体赛为 `每局分数 × groupsValid`（默认 3）。
- 判定：0:0 非法、平局非法、双方都未到满分则**强制继续**（“本场比赛为连续追分，本局未满 N 分”），
  到满分后分高者胜。
- 单场记录的是「本场新增比分 = 当前累计 − 上一场累计」，不能为负。

## 5. 快捷比分

```
a = round(0.5  × balls)  取偶
c = round(0.77 × balls)  取偶
o = balls
追分模式再各加 (order − 1) × balls
```

例：21 分制 → `12 / 16 / 21`；15 分制 → `8 / 12 / 15`。

## 7. 积分与排名

### 7.1 统计口径（`rank.js`）

| 字段 | 含义 |
| --- | --- |
| `wins` / `fail` / `even` | 按**场**统计（比较局分 `scoreAll`） |
| `winRound` / `failRound` / `net` | 按**局**统计，`net` = 胜局 − 负局 |
| `winball` / `failball` / `netball` | 按**分**统计，`netball` = 得分 − 失分 |
| `point` | 积分 |
| `rate.alls` / `rate.net` / `rate.netball` | 胜率 / 局胜率 / 分胜率 |

**积分算法**：一场比赛内累加每局 `+1`（胜）或 `−1`（负）得到 `s`；

- `s > 0` → 得 `s` 分；若该场只有一局，直接得 2 分
- `s = 0` → 双方各 1 分
- `s < 0` → 对手得 `|s|` 分（单局同样记 2 分）

即：2:0 得 2 分、2:1 得 1 分、单局胜得 2 分。

### 7.2 排序链

原实现用多次稳定排序叠加，最后一次为主键。本项目等价写成优先级链（前者优先）：

| 排名方式 | 排序优先级 |
| --- | --- |
| `pointFirst` 积分优先 | 积分 → 胜场 → 净胜分 → 胜率 → 局胜率 → 分胜率 |
| `ballFirst` 净胜分优先 | 净胜分 → 胜场 → 总得分 → 积分 → 胜率 → 局胜率 → 分胜率 |
| `totalFirst` 总得分优先 | 总得分 → 净胜分 → 胜场 → 积分 → 胜率 → 局胜率 → 分胜率 |
| `winsFirst` 胜场优先 | 胜场 → 胜场差 → 净胜局 → 积分 → 净胜分 → 总得分 → 胜率 → 局胜率 → 分胜率 |

> 源码里 `ballFirst` / `totalFirst` 的第二关键字写的是
> `n._wins - n._fail - (t._wins - n._fail)`，等价于「胜场数比较」而非「胜场差」。
> 本项目按**实际行为**复刻（胜场数），并在 `ranking.js` 注释标明。

### 7.3 排名主体

- 个人赛（八人转/混双转/前后转/单打转/循环赛/擂台赛/晋级赛/自由转）：按人排名。
- 对抗赛与团体赛：按队伍排名，单项比分汇总到队伍。

### 生成算法说明

原包的对阵由云函数 `preview` 生成，**未随包下发**。本项目按上表语义实现：

- 循环类（`loop`/`doubleLoop`/`singlesLoop`/`singlesRound`/`fixedRound`）：轮转法（circle method），
  保证两两相遇；`fixedRound`/`singlesRound` 以「出场次数上限」截断。
- 八人转：轮转法先得到 n−1 轮、每轮 n/2 组搭档（搭档全局唯一），再把每两组搭档组成一场，
  每轮 `floor(n/4)` 场，不足 4 人整倍数时轮空。
- 混双转/前后转：先生成全部搭档组合，再贪心排轮，保证同一轮选手不重复、每个搭档恰好一次。
- 擂台赛：前 k 人为擂主，其余人依次攻擂。
- 对抗/团体：队内配对或轮转后跨队配对；团体赛按队队循环生成。

如需与原服务端逐场一致，需要拿到 `preview` 云函数的实现；当前实现保证规则语义一致。

## 9. 本项目对原实现的取舍

| 原实现 | 本项目 | 原因 |
| --- | --- | --- |
| 比分提交到云函数，多端同步 | 本地存储 | 无云环境；需要多人同步时按 AGENTS.md 接入云开发 |
| 赛制由服务端生成 | 客户端生成 | 服务端代码未下发 |
| 排名由服务端返回 `ranks` | 客户端计算 | 同上；排序链已按源码复刻 |
| 支付、俱乐部、广告 | 不包含 | 依赖资质与第三方 SDK |
